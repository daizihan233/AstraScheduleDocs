# 其他

## 和风天气 API 有什么限制？免费版够用吗？

**API Key 方式（简单）：**

| 限制项 | 数值 |
|--------|------|
| 每日调用量 | 1000 次 |
| 每分钟最大调用量 | 300 次 |
| 计费方式 | 按调用量计费 |

受网络等各类因素影响，可用以下公式做保守估算（按每个班级每天最多刷新 2 次计算）：

- 每日调用量 ≈ 班级数 × 2
- 每分钟最大调用量 ≈ 班级数 × 2（全部班级同时刷新的极端情况）

**JWT 方式（建议）：**

- 无调用次数限制
- 需要填写开发者认证信息（免费申请）

建议注册和风天气开发者账号后，使用 JWT 认证方式，免费且不受调用量限制。配置方法：在 `config.toml` 中使用 JWT 格式的 API Key。

## 浏览器兼容性如何？

管理端基于现代 Web 技术构建，建议使用以下浏览器：

| 浏览器 | 最低版本 | 推荐版本 |
|--------|----------|----------|
| Chrome | 90+ | 最新版 |
| Edge | 90+ | 最新版 |
| Firefox | 90+ | 最新版 |

不支持的浏览器：IE 全系列、旧版 Edge（EdgeHTML 内核）。

## Windows 7 上能正常运行吗？

AstraSchedule 客户端支持 Windows 7，这正是此项目诞生的原因之一。

## 如何迁移数据到新服务器？

1. 在旧服务器上，通过管理端「实用工具」→「导出备份」，下载 JSON 备份
2. 复制旧服务器的 `config.toml` 配置文件
3. 在新服务器上部署 AstraSchedule 后端
4. 将 `config.toml` 放到新服务器的对应位置（修改为新服务器的 IP/域名）
5. 启动新服务器后端
6. 打开管理端，进入「实用工具」→「导入还原」，选择之前下载的 JSON 备份
7. 验证所有班级配置正确
8. 更新客户端配置的后端地址，指向新服务器

## 后端端口 9000 起不来 / 提示端口被占用？

Windows 上 9000-9099 端口可能被 Hyper-V 预留。处理方式：

1. 换个端口：修改 `config.toml` 的 `server.port`（如 `9100`），并同步更新客户端「云端服务」地址与管理端登录页后端地址
2. 或检查占用：`netstat -ano | findstr 9000` 查看占用进程

## 客户端课表时间不准？

客户端计时基于**本机系统时间**，请先确认电脑系统时间与网络时间一致：

- 在 Windows 设置中开启「自动设置时间」（NTP 同步）
- 如仍偏差，可用托盘「调试选项」→「调试输入」设置时间偏移秒数（正数延后、负数提前）进行校准

## 管理端后端地址在哪里修改？

登录页的「后端地址」输入框即可修改，保存在浏览器本地（localStorage），改完重新登录即可生效，无需改代码或重新部署。只有想修改登录页**默认值**时才需要改源码重新构建。
